A write-up of the project

An AI mentor that refuses to write the code for you.

Mentivo turns your project idea into a personalized roadmap, walks you through every milestone, and checks that you actually understood what you built before letting you move on. It will not generate the code on your behalf. That is the whole point.

01The problem I kept noticing

Over the last year I watched a particular pattern repeat itself, mostly with non-technical founders and people new to building. It goes like this. They open a chat window with an AI coding tool, describe the app they want, and accept whatever it writes. The first version usually works. The second prompt breaks something. By the fourth or fifth iteration nobody knows what the code does or why a change in one place blew up something else, and the tokens keep burning while the project tangles itself into a corner.

I am not trying to say everyone needs to read every line of what an AI produces. That would defeat the point of the tool. But there is a gap between writing every line yourself and understanding none of it, and almost nobody is building for that gap. The result is a category I’ve started calling deep AI slop: software that runs, looks complete, and falls apart the moment something needs to change.

The frustrating part is that the fix is small. A user does not need to memorize syntax or master a framework. They need to know what their app is made of, what each piece is doing, and what the failure modes look like. Once that exists, working with an AI tool becomes a real collaboration instead of a guessing game.

02Why I cared enough to build it

I learned to code through Codecademy and freeCodeCamp. Both of them were good at the “what to type” part and not as good at the “why it works” part. For a long time I could finish a course and still not be able to build the simplest app on my own. That was not anyone’s fault. It is just what passive learning does.

A few years later I ended up working at Skillsoft, which owns Codecademy, as a software engineer co-op on the AI content platform. Working there clarified a few things. I saw how much effort goes into the content, how cost-sensitive AI features are at scale, and how hard it actually is to measure whether a learner walks away able to do anything. The whole time I kept thinking about the gap I had hit as a learner. And about the founders I’d been watching outside of work, who were running into a version of the same thing from the other side: building apps they could not maintain.

Mentivo is the thing I wanted when I was learning, built with the production-grade pieces I learned to care about while I was working. I made it opinionated on purpose. The AI explains, asks questions, and quizzes you, but it will not paste the answer for you.

One thing I keep coming back to If you can’t explain what your app is doing after you ship it, you haven’t really shipped it. That’s the thing I want Mentivo to prevent.

03What it actually is

A web app. You type your idea in plain English. A short conversation shapes the scope. A six-question adaptive quiz figures out your level. You get a 5–8 milestone roadmap built specifically for your project. Each milestone has a concept page, a starter scaffold, a Socratic chat tutor, and an in-browser code editor with live preview. After each milestone there’s a knowledge check on the exact concepts you just built. Pass and you unlock the next milestone. Fail and the tutor uses what you got wrong to adjust the next conversation.

Under the hood it is one Next.js app on Vercel with nine LLM call-sites, a serverless Postgres database, Google Gemini behind the Vercel AI SDK, and a Langfuse trace on every AI call. There is also a small offline eval suite that runs against three of the trickier prompts before changes ship.

04How a session works

The five flows below sit behind five different API routes. Together they make the “idea → shipped project” path the user walks.

01
Onboarding chat
You describe your idea. A streaming chat narrows scope to something a beginner can actually finish. The conversation summary feeds the next step.
POST /api/chat  ·  prompt: onboarding-chat  ·  streamText
02
Adaptive skill quiz
Six tiered questions generated for your specific project, not a generic quiz. Your score sets your starting level: beginner, intermediate, or advanced.
POST /api/quiz/generate  ·  covered by the quiz-generate eval suite
03
Roadmap generation
A structured 5–8 milestone roadmap, produced with generateObject and validated against a Zod schema. Each milestone has a concept, an order, a duration estimate, and a difficulty tier.
POST /api/roadmap/generate  ·  covered by the roadmap-generate eval suite
04
Milestone workspace
A concept page in markdown, a starter scaffold, a Monaco multi-file editor with live preview, and a chat tutor scoped to the current milestone. The tutor is instructed to ask Socratic questions instead of handing over working code.
POST /api/milestone/{concept, starter, chat, verify-tasks}
05
Knowledge check
A tailored quiz on the exact concepts you just used. Pass and the next milestone unlocks. The pattern of wrong answers gets fed back into the next milestone’s tutor context.
POST /api/milestone/quiz-generate  ·  /api/milestone/quiz-evaluate

05The stack — and why each piece is there

Every layer below earned its place because the alternative was worse for this specific app. Single language, single deploy target, smallest surface area I could get away with.

Frontend & runtime Next.js 16 on Vercel
The product is one app: marketing site, learner dashboard, API routes for the AI, auth. Next.js App Router gives me all of that in one runtime, with React Server Components by default so I am not shipping JavaScript I do not need. Vercel gives me previews per branch, edge caching for the static parts, and serverless functions for the AI routes without me running infra.
Language TypeScript, end to end
Same types from the database, through the API routes, into the React components. Prisma generates the DB types, Zod schemas validate the AI outputs, and the rest of the app consumes both. If I rename a field, the build tells me everywhere I missed.
AI client Vercel AI SDK
streamText handles the chat surface, generateObject handles the structured outputs (roadmap, quiz). The SDK has built-in OpenTelemetry hooks, which is what makes the Langfuse integration trivial. It is also provider-agnostic, so swapping from Gemini to Claude or GPT-4o is one import in src/lib/ai.ts.
Model Google Gemini 2.5 Flash
Cheap, fast, with a generous context window for the cases where I have to pass the whole conversation summary plus the milestone history. Quality is good enough for conversational tutoring at this stage. The provider layer stays thin so I can move if a better model shows up.
Observability Langfuse + OpenTelemetry
Every AI call goes through one withTracing() helper that attaches the prompt name, the prompt version, the user ID, and the project ID. When a regression shows up I can answer “which prompt version, which users, which inputs” in one query instead of grepping logs. The exporter is OTel-native so I can ship the same traces to a different backend later without rewriting the call sites.
Evals promptfoo
Three suites live in evals/: roadmap, quiz, and milestone starter. Each test combines programmatic assertions on the structure (length, schema, required fields) with llm-rubric assertions on the quality (“are these questions actually about the project the user described?”). Run with one command. A change to a prompt that breaks either layer fails before it ships.
Database Prisma + Neon Postgres
The data is genuinely relational: users, projects, milestones, messages, quiz attempts. So Postgres, not a key-value store. Neon’s serverless driver uses HTTP transactions, which keeps cold starts low on Vercel functions. Prisma gives me typed queries and a migration story I can trust.
Auth NextAuth v5
Email + password and Google OAuth out of the box, with a Prisma adapter that keeps users in the same database as everything else. Every API route checks the session and enforces project ownership before touching data.
Editor Monaco
The same engine VS Code uses, running in the browser. Multi-file aware, with live preview wired up so the learner can change a file and see the result in the same window. No npm, no terminal, no install on day one.
Styling & motion Tailwind v4 + GSAP
Tailwind keeps the design system in one place; the entire site uses a single accent colour (amber). GSAP handles the scroll-driven moments on the landing page, including a pinned horizontal section for the “how it works” story.
Tests Vitest + Testing Library
Unit tests on the pure logic that does not need a model (quiz scoring, prompt compilation, validators). The AI surface is tested by the eval suites, which is the layer that matters for that kind of code.
CI/CD GitHub Actions → Vercel
Typecheck, lint, and tests run on every PR. Vercel auto-builds a preview URL per branch. Production deploys on merge to main. The eval suite is wired in as an opt-in job because it costs tokens.

07The AI infrastructure layer

Most early-stage AI apps skip this part. I’ve seen what happens when you do. A prompt changes, quality drops in production a week later, and no one can tell which version of which prompt ran for which user. So you guess. The fix is pretty simple, even if it’s a bit of upfront work: version every prompt, trace every call, and run an offline check before a prompt change ships. That’s the spine the rest of this section sits on.

Where the prompts live

Every prompt lives in src/lib/prompts/<name>.ts and registers itself into a runtime registry at module load. Routes only ever ask for a prompt by name. If a prompt is missing, the app fails on startup, not at the moment a user hits the route.

src/lib/prompts/registry.tsexcerpt
export function registerPrompt<T extends PromptVariables>(config: PromptConfig<T>): void {
  registry.set(config.name, config)
}

export function getPrompt<T extends PromptVariables = PromptVariables>(name: string): PromptConfig<T> {
  const prompt = registry.get(name)
  if (!prompt) {
    const available = [...registry.keys()].join(', ')
    throw new Error(
      `Prompt "${'$'}{name}" not found in registry. Registered prompts: [${'$'}{available || 'none'}]`
    )
  }
  return prompt as PromptConfig<T>
}

export function getPromptVersion(name: string): string | undefined {
  return registry.get(name)?.version
}

Tracing every call

One helper builds the experimental_telemetry object the Vercel AI SDK forwards to OpenTelemetry. Every trace lands in Langfuse tagged with the prompt name, the prompt version, the user ID, and the project ID. Nothing escapes the contract, because the contract is a function the route handlers call instead of an instruction in a doc nobody reads.

src/lib/tracing.tsexcerpt
export function withTracing(promptName: string, metadata: TracingMetadata = {}) {
  return {
    experimental_telemetry: {
      isEnabled: true,
      functionId: promptName,
      metadata: {
        promptVersion: getPromptVersion(promptName) ?? 'unknown',
        ...metadata,
      },
    },
  }
}

// Used at every call site:
const result = await generateObject({
  model,
  schema: RoadmapSchema,
  prompt: compiled,
  ...withTracing('roadmap-generate', { userId, projectId }),
})

Evals that check both structure and quality

Three suites run via npm run eval. Each test mixes programmatic JavaScript assertions on the structure with an llm-rubric assertion on the semantics. A regression in either layer fails the suite.

evals/quiz-generate.yamlexcerpt
tests:
  - description: "Weather dashboard — 6 tiered questions relevant to the project"
    vars:
      idea: "Weather dashboard that shows 5-day forecast with charts"
    assert:
      - type: javascript
        value: "JSON.parse(output).questions?.length === 6"
      - type: javascript
        value: "JSON.parse(output).questions?.every(q => q.options?.length === 4
                  && q.options.some(o => o.id === q.correctId))"
      - type: javascript
        value: "new Set(JSON.parse(output).questions?.map(q => q.difficulty)).size >= 2"
      - type: llm-rubric
        value: "Questions should be relevant to building a weather dashboard —
                testing concepts like API calls, data display, and chart
                rendering, not unrelated topics."

Streaming responses, saving them after

The chat surface streams to the UI via the Vercel AI SDK and persists the assistant message in onFinish. The stream and the database write are decoupled, so the user sees the response immediately and the write happens once the stream finishes.

src/app/api/chat/route.tsexcerpt
const result = streamText({
  model,
  system: getPrompt("onboarding-chat").template({ idea: project.idea }),
  messages: modelMessages,
  ...withTracing("onboarding-chat", { userId, projectId }),
  onFinish: async ({ text }) => {
    await prisma.message.create({
      data: { projectId, role: "assistant", content: text },
    });
  },
});

return result.toUIMessageStreamResponse();

08Engineering practices that are already in

Security
Rate limiting + CSP
Per-user limiter on every AI route. CSP headers and input validation at the middleware layer.
Errors
Typed AI error envelope
AIGenerationError wraps provider errors with a stable shape for the UI. Users see a graceful message, traces still carry the underlying stack.
Logging
Structured logger
JSON output, level + context per line. Designed for Vercel log drains and Langfuse correlation.
Types
TS strict + Zod schemas
No any. Every AI structured output runs through a Zod schema before it reaches the database.
Tests
Vitest + Testing Library
Unit tests on the pure logic. Eval suites cover the AI surface.
CI/CD
GitHub Actions → Vercel
Typecheck + lint + tests on every PR. Preview per branch. Production on merge.

10Where it goes from here

Mentivo today is a focused beginner workspace. The version in my head is a bit more ambitious. Two threads I want to pull on next.

One-click launch of the finished project

Right now a learner finishes their milestones and has a working app in the browser. I want the “done” button to do something real: package the project in a container, hand the learner a downloadable bundle and a one-click deploy. The Monaco editor already manages multi-file state, so the missing piece is the build-and-bundle step, not the editing experience. Containerizing each project also opens the door to running backends inside Mentivo, not just static frontends.

Closing the feedback loop on AI quality

A small thumbs-up / thumbs-down on every AI output, persisted to Postgres and posted as a Langfuse score on the matching trace. With that in place, every bad response automatically becomes a candidate test case for the next eval run. Small bit of UI, but it’s the difference between hoping the AI is good and actually knowing when it isn’t.

The rest of the honest gap list

  • Playwright happy-path e2e One scripted run: signup → idea → quiz → roadmap → first milestone passes. Catches the regressions that matter most.
  • PostHog product analytics The day there is a funnel question Vercel Analytics can’t answer. Not before. An empty dashboard is worse than no dashboard.
  • SLO on p95 streaming latency The first time a user says “the AI feels slow,” this stops being optional. Langfuse already has the timing; this is just a dashboard with a threshold on top.
  • Sentry The day a human is paged when it fires. Until then Vercel logs and Langfuse cover what matters.
  • Tool-using tutor Let the milestone chat read the learner’s current code from the Monaco editor as a tool call, and reference it in its hints. Promotes the tutor from “chat in a tab” to actual pair-programmer.
